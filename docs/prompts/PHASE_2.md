# Phase 2: analytics and review workflow
Read COMMON_RULES.md first. Branch `phase2-analytics`. Spec: `docs/NEXT_BUILD_BRIEF.md` items 5 to 10. Do the tasks in order; finish each one (code, tests, check) before the next.

Where things are: `src/lib/metrics.ts` (pure engine; already has expectancy, max drawdown, win/loss streaks, profit factor, equity curve), `src/lib/trades-data.ts` (`loadTrades` loads up to 10,000 rows into memory; `RANGES`), pages `src/app/app/page.tsx` (dashboard), `src/app/app/analytics/page.tsx`, `src/app/app/journal/page.tsx`, scope/account switcher in `src/lib/app-context.ts`, timezone helpers in `src/lib/timezone.ts` (`localDate`, `localDayHour`: use them for calendar days and heatmaps in the user's zone). Table `tradenotes.reviews` exists (period only 'day' or 'week', columns went_well, to_improve, focus_next).

## Tasks
1. **Filter bar (item 5).** One shared component and one parser in `src/lib/filters.ts`: date range (existing presets plus custom from/to), account (existing scope), strategy, instrument, side, tags (mistake/emotion), session. State lives in the URL query string. Used by dashboard, analytics, journal and the calendar. Invalid values are ignored, never errors. Check: unit tests for the parser (garbage input, repeated params) and an e2e that sets two filters and sees totals change.
2. **Push filtering and aggregation into SQL (item 10, do early).** Replace "load everything then filter in JS" for the dashboard and analytics: filters become SQL conditions; headline totals and group tables aggregate in SQL with indexes (add `db/paste/12_*.sql`; consider (user_id, closed_at), (user_id, symbol)). Keep the metrics engine as the single source of truth for formulas: either aggregate per-trade results in SQL and feed `summarize`, or reproduce formulas in SQL and assert equality in a test on a seeded dataset. Remove the "more than 10,000 trades, oldest 10,000 only" truncation. Check: a seeded 10,000-trade test; record server timings for dashboard and analytics in the QA file; target under 1.5 s.
3. **New analytics (item 6).** In pure functions in `src/lib/analytics-extra.ts` with hand-calculated tests: R-multiple distribution (buckets), time-of-day by weekday heatmap (user's time zone), hold-time buckets, mistake-cost report (P&L of trades carrying each mistake tag; a trade with several tags counts under each, say so on the page), profit factor with sample-size warning (keep the no-infinity rule), drawdown with recovery (peak, trough, trades to recover or "not recovered"). MAE/MFE only if the owner wants it: it needs new nullable columns and entry fields; skip it and list it as not built unless asked. Show each on `/app/analytics`; keep the "fewer than 30 trades" warnings.
4. **Calendar view (item 7).** `/app/calendar`: month grid of daily net P&L and trade count in the user's time zone, weekly summary column, click a day to open the journal filtered to that day, colour-blind-safe scale (not red/green only: also use sign and intensity labels). Works at 390px. Add to nav.
5. **Daily journal and weekly/monthly reviews (item 8).** Migration: allow `period` 'month' in the check constraint (idempotent: drop and re-add the constraint by name). Page `/app/reviews`: templates (what worked, what to repeat, mistakes, rule breaks, next-period plan), stats auto-filled from the period's trades, history list, edit. Reviews are plan-gated Standard and up on the server. Reminder email: **only if the owner confirms a scheduler exists at no extra cost** (ask; Vercel Cron availability depends on the plan). If not confirmed, do not build the email and list it under "not built".
6. **Playbook (item 9).** Strategies already exist (`tradenotes.strategies` has `rules`). Add checklist items per strategy and per-trade adherence: new tables need RLS and isolation checks (see rules; update `EXPECTED_TABLES`). On the trade form, tick the checklist; show adherence % per strategy and an adherence-vs-results comparison in analytics. Limit counts per plan if sensible and enforce on the server.
7. **Plan copy.** Move shipped features from `FEATURES_DEV` to `FEATURES_NOW` in `src/lib/plan-features.ts`; update `PLANS`, pricing, billing copy, landing "built" list and tests together. Remove them from "in development" text only when shipped and tested.
8. **Finish** with the "After the phase" list in COMMON_RULES.md. In the QA file include the 10,000-trade timings and the Free/Standard/Premium matrix for each new page.
